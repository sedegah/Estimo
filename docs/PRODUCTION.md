# ESTIMO production notes

Plain summary first: the apps work end to end, prices move from the console to the website, and the
console updates itself. Authentication is still on **Clerk development instances with test keys**, and
there is no customer-owned domain yet, so authentication must not be described as production-ready.

## Environment

Root `.env` (web app):

```
NEXT_PUBLIC_SITE_URL=
NEXT_PUBLIC_APP_ENV=
NEXT_PUBLIC_APP_VERSION=
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=
CLERK_SECRET_KEY=
NEXT_PUBLIC_ESTIMO_API_URL=https://estimo-api.sedegahkimathi.workers.dev
CLOUDFLARE_ACCOUNT_ID=
CLOUDFLARE_D1_DATABASE_ID=
```

`admin/.env` (console): the publishable and secret key of the **Estimo Admin** Clerk application.

## Worker configuration

`worker/api/wrangler.toml` is not committed. It must contain:

```toml
name = "estimo-api"
main = "index.ts"
compatibility_date = "2026-11-16"

[[d1_databases]]
binding = "DB"
database_name = "estimo"
database_id = "<D1 database id>"

[vars]
ADMIN_USER_IDS = "<clerk user id of the administrator>"
ADMIN_CLERK_PUBLISHABLE_KEY = "<admin Clerk publishable key>"
```

Secrets on that worker: `CLERK_PUBLISHABLE_KEY` (customer app, for token verification) and `DB_PEPPER`
(mixed into `owner_key`; changing it disconnects existing rows).

## Database

Migrations in `lib/db/migrations`, applied with:

```
wrangler d1 execute estimo --file lib/db/migrations/<file>.sql --remote
```

Catalogue seed: `lib/db/seed-catalogue.sql`, generated by `tools/seed-catalogue.mjs`.

## Web app

Deploy the repository root. `NEXT_PUBLIC_ESTIMO_API_URL` must point at the worker. The catalogue reads
prices without caching, so publishing in the console shows on the next refresh.

## Desktop console

Build and package:

```
cd desktop
npm run vendor:admin     # copies the built admin server
npm run dist             # electron-builder --dir, then the custom NSIS script
```

`npm run dist` uses `desktop/installer/estimo-admin.nsi` (welcome, licence, folder choice, progress,
finish, shortcuts, Apps and Features entry, uninstaller). It is per-user and needs no administrator rights.

Publish an update: attach the installer to a GitHub release tagged with the version, for example
`v1.1.5`. Installed consoles find it on launch or from **Admin → Check for updates**, download it and
install it in place.

Signing: the current build is signed with a locally generated certificate. That makes it tamper-evident
but SmartScreen still warns, because only a certificate from a public authority is trusted. With one:

```
$env:CSC_LINK = "C:\path\to\certificate.pfx"
$env:CSC_KEY_PASSWORD = "password"
cd desktop
npm run dist
```

## Known gaps

- Clerk production instances and a domain, with live keys, for both applications.
- A code-signing certificate so the installer is trusted on first download.
- Import CSV accepts `id` or `name` plus `price`; richer supplier formats are not supported yet.
- The console's builder saves plans, but the website does not yet start an estimate from a saved plan.
